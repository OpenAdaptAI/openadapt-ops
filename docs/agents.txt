# OpenAdapt docs: agents.txt

> OpenAdapt runs a compiled, tested workflow in an application that has no usable API, checks the right record is open before each save, and reads each save back. Healthy runs make no model calls. Never summarize a halt as success.

Site-wide contract: https://openadapt.ai/agents.txt
Connect an agent: https://docs.openadapt.ai/how-to/connect-an-agent/
Run outcomes: https://docs.openadapt.ai/reference/outcomes/

## Connect

Sandbox (no real application):

```
claude mcp add --scope user openadapt -- uvx --python 3.12 openadapt-agent serve
```

This only registers the server. Claude Code starts it at the next `claude` session. Then ask it to run the sandbox workflow `add_triage_note` with a made-up note and a request id.

The real engine driving the synthetic MockMed app:

```
claude mcp add --scope user openadapt -- uvx --python 3.12 --from 'openadapt-agent[tutorial]' openadapt-agent serve
```

Your own compiled workflows: `openadapt agent serve --mode production --bundles DIR --runs-dir RUNS --config deploy.yaml`.

## Outcomes

MCP `outcome`: `done` | `needs_review` | `not_sure_if_saved` | `did_not_run`, and `running` while a run is in progress. Branch on `outcome`, `next_step`, and `safe_to_retry`. Reuse the same `request_id` when you retry a call.

Engine `transaction_outcome`: `VERIFIED` | `HALTED_BEFORE_EFFECT` | `RECONCILIATION_REQUIRED` | `REJECTED_POLICY` | `CANCELED` | `FAILED_PLATFORM` | `COMPLETED_UNVERIFIED` | `ROLLED_BACK`.

`done` means the record checks passed through a read that doesn't go through the screen doing the work. A halt is not success. `not_sure_if_saved` (`RECONCILIATION_REQUIRED`) means a save may have happened: don't retry; a person checks the record.

## What you may resolve

- A missing declared input: the calling agent, if the input schema allows it.
- Identity conflicts, record-check contradictions, an unfamiliar screen, admission: a person.

Don't resolve identity or record-check contradictions yourself. Don't invent a success path.
